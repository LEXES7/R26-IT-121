Stratified VAE with Dual-Signal Anomaly Attribution

Per-type variational autoencoders for unsupervised fraud detection and intrinsic attribution

DeepSentinel — Multi-Modal Financial Fraud Detection Platform · Project R26-IT-121
Component Author: Wijesinghe L.P.D.B. (IT22109194) · Member 2
Supervisor: Mrs. Anjalie Gamage

1Component Overview

The Stratified VAE is the behavioural-modality detector of the DeepSentinel platform. It learns a generative model of normal transaction behaviour separately for each transaction type, then scores unseen transactions by how poorly that model reconstructs them. Unlike the relational detector (GraphSAGE, Member 1) which models account-to-account connections, and the temporal detector (TS-TCN, Member 3) which models sequence escalation, this component models what a normal transaction of a given type looks like and flags departures from it.

It is the only fully unsupervised detector in the platform: every VAE is trained on non-fraud transactions alone, so no fraud labels enter training. This matters operationally — the component can flag fraud patterns absent from any historical label set.

Role within the platform

  • Input: a batch of transactions — a transaction log uploaded as CSV (PaySim schema in development; any mobile-money log in deployment). Feature engineering runs over the batch, each row is routed to the VAE for its transaction type, and every row is scored.
  • Output: per transaction, a behavioural anomaly score and a per-type threshold decision; for each flagged transaction, an anomaly fingerprint — a 29-dimensional attribution vector with a discovered fraud typology label. The batch result is the reduced set of flagged transactions with their attributions.
  • Downstream consumer: Member 4's Fusion Engine, which combines this output with the GraphSAGE and TS-TCN outputs.
  • Join key: composite_id, formatted nameOrig_step.
Scoring granularity — batch pipeline, row-independent model

The VAE itself imposes no cross-transaction dependency: each row is encoded, reconstructed and scored on its own, unlike the TS-TCN (which requires a 32-transaction window) or GraphSAGE (which requires a constructed graph). The normalisation statistics, per-type thresholds and latent cluster centres are fitted once on the validation partition and persisted in stratified_config.json, so scoring a row needs no other rows.

The batch requirement comes from feature engineering, not from the model. Two of the thirteen features are computed as dataset-level aggregates: F8_is_large compares the amount against a per-type 95th percentile derived from non-fraud rows, and F11_account_velocity is the log transaction count for the originating account across the log. Single-transaction inference would therefore require the three F8 percentile constants to be persisted alongside the model, and a per-account counter to be served from state. Neither is a limitation of the detector, but both must be resolved before a per-transaction API can replace the batch path.

2The Sub-Problem Addressed

  • A single global model averages incompatible behaviours. TRANSFER, CASH_OUT and PAYMENT have structurally different amount and balance distributions. One VAE fitted across all three learns an average of behaviours that never co-occur, reconstructing no type well and separating fraud within none — the global baseline reaches F1 0.0165.
  • Anomaly scores arrive without a reason. A reconstruction error states that a transaction is unusual but not in what respect, leaving investigators unable to act. Post-hoc explainers such as SHAP add inference latency incompatible with real-time screening.
  • Fraud typologies are assumed rather than discovered. Supervised detectors reproduce the categories present in their labels; a system expected to surface novel fraud must derive its typologies from the data.

3Novel Contributions

N1 — Type-stratified VAE ensemble

One VAE, one MinMaxScaler and one decision threshold per transaction type. Fitting the scaler within type prevents cross-type scale leakage; sizing the architecture per type allocates capacity where the behaviour is harder to model.

N2 — Dual-Signal Anomaly Attribution (DSAA)

Attribution is read directly out of the VAE objective, with no auxiliary explainer and no added latency. Signal 1 is the per-feature share of total reconstruction error — which of the 13 features the model failed to reproduce. Signal 2 is the per-latent-dimension share of total KL divergence — which axes of learned normal behaviour the transaction departs from. Concatenated, they form a 29-dimensional anomaly fingerprint.

N3 — Characterising the β region in which native KL attribution stays informative

Signal 2 is only meaningful when the latent space carries information. Under a strong KL penalty every dimension collapses onto the Free Bits floor, attribution becomes uniform, and Signal 2 degenerates to a constant. This work maps that failure boundary empirically (Section 6) and selects β from it by a criterion fixed in advance. To our knowledge no prior work on VAE-based fraud detection reports the β region within which native KL attribution remains discriminative.

N4 — Unsupervised typology discovery from anomaly fingerprints

DBSCAN over the fingerprints groups fraud cases that fail in the same way, producing named typologies without fraud-category labels.

5Model Architecture

Each VAE is a symmetric encoder–decoder with a Gaussian latent layer, trained only on non-fraud transactions of its own type under an 80/20 train/validation split.

Table 2 — Per-type architecture and training partition
StratumEncoderLatent dimTraining rowsRole
TRANSFER13 → 32 → 168423,049Primary fraud leg
CASH_OUT13 → 64 → 32161,786,707Secondary fraud leg
PAYMENT13 → 32 → 168—False-positive control (zero fraud)

Training configuration. Adam (lr 1×10⁻³), batch 256, up to 60 epochs. Free Bits floor 0.1 nats per latent dimension. β annealed linearly 0 → 0.05 over 10 epochs, then held. Early stopping monitors val_recon_loss with patience 8, deferred until epoch 12.

Design note — why early stopping cannot monitor total loss

The total loss contains the term β·KL, and β rises every epoch during annealing, so the monitored quantity increases by construction. An earlier revision monitored val_total_loss, stopped at epoch 6 and restored the epoch-1 weights — a point at which β = 0, i.e. a plain autoencoder with no latent regularisation at all. Reconstruction loss carries no β term and is a valid stopping signal throughout. Deferring the stopping decision until annealing has finished ensures no decision is taken while the objective is still changing shape.

6Latent-Space Validation

Signal 2 is derived from per-dimension KL divergence, so it is informative only while the latent space remains active. β was therefore swept on the TRANSFER stratum, with the selection rule fixed before the results were seen: take the largest β that keeps at least half the latent dimensions active and a Signal-2 spread above 0.02.

8Typology Discovery

DBSCAN (ε = 0.108, min_samples = 10, Euclidean) over the 29-dimensional fingerprints of all 8,213 fraud cases yields 12 clusters with 505 noise points (6.1%) and a silhouette score of 0.239. Four typology families emerge, each named from its dominant attribution components.

Evidence that Signal 2 became discriminative. In the earlier revision the same three latent dimensions dominated every discovered cluster — the signal was a constant background rather than an attribution. After correction, each cluster is dominated by a distinct latent dimension (3, 6, 8, 1 and 0 respectively) with weights roughly doubled. The mean Signal-2 non-uniformity rose from 0.0400 to 0.0716. This is the central experimental result of the component: the correction is what makes N2 and N4 mean anything.

9Known Limitations

Stated plainly, since each is likely to be raised in review.

  • CASH_OUT detection is weak and cannot be fixed by tuning. Sweeping the decision threshold across the full precision–recall curve gives a maximum attainable F1 of 0.1263, against 0.0961 achieved. The limit is the representation, not the operating point. Fraudulent CASH_OUT transactions are only identifiable through their linkage to a preceding TRANSFER — a relational and temporal property this component cannot observe. This is the gap the GraphSAGE and TS-TCN components are designed to fill, and is the empirical justification for the multi-modal ensemble.
  • The correction improved ranking but not CASH_OUT detection. AUC-ROC rose from 0.9119 to 0.9646 while F1 fell from 0.1766 to 0.0961. The KL regularisation that makes the latent space interpretable also smooths the reconstruction tail that the unregularised model was exploiting. This is a measured trade-off, accepted because latent-space validity is a precondition for the attribution contribution.
  • Discovered clusters are type-pure by construction. Signal 2 is zero-padded to the maximum latent dimension, so TRANSFER fingerprints occupy an 8-dimensional subspace and CASH_OUT a 16-dimensional one; the minimum cosine distance between the two groups is 0.2056. Typology discovery therefore operates within each stratum — consistent with the stratified architecture, but it means the clustering does not relate typologies across types.
  • β was swept on TRANSFER only, under a fixed compute budget, then verified post hoc on all three strata via the latent health check in Table 4.
  • AUC-ROC is optimistic at this class balance. Fraud is 0.18% of CASH_OUT, so an AUC of 0.9646 coexists with an F1 of 0.096. Average precision is the appropriate summary statistic.

10Output for the Fusion Engine

For each transaction in the submitted batch the component returns a behavioural anomaly score and a per-type threshold decision; for each flagged transaction it additionally returns an anomaly fingerprint block carrying the ranked Signal 1 features, the ranked Signal 2 latent dimensions, and the assigned typology label with its cluster identifier. The join key across all modules is composite_id, formatted nameOrig_step, so the three detectors' outputs align row-for-row on the same uploaded log.

The recommended fusion policy follows directly from Table 5: route by transaction type rather than averaging scores. This component should carry the TRANSFER leg, where it reaches F1 0.9836, and defer the CASH_OUT leg to the relational and temporal detectors. Reporting the aggregate Configuration D figure as this component's performance would understate its contribution on the leg it resolves.
